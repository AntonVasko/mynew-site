Исключения в Python

Обработка ошибок: try / except / else / finally, встроенные исключения, raise, assert, свои исключения, менеджеры контекста и группы исключений. В конце — мини-проекты. Комментарий # показывает результат.

Основы: что такое исключение

Исключение — объект-сигнал об ошибке во время работы программы. Если его не обработать, он поднимается вверх по цепочке вызовов, и программа завершается с трассировкой (traceback).

Ошибка без обработки

def divide(a, b):
    return a / b

def main():
    print(divide(10, 0))

main()
Traceback (most recent call last):
  File "app.py", line 7, in <module>
    main()
  File "app.py", line 5, in main
    print(divide(10, 0))
  File "app.py", line 2, in divide
    return a / b
ZeroDivisionError: division by zero

Как читать traceback

  • Читайте снизу вверх: последняя строка — тип и сообщение ошибки.
  • Строка над ней — место, где ошибка возникла.
  • Выше — цепочка вызовов, которая к ней привела.
  • Сообщение File … line N показывает файл и строку.

Ошибка синтаксиса и исключение

SyntaxError возникает до запуска (код не разобрался). Исключения возникают во время работы, и их можно перехватить.

print("привет"          # SyntaxError — программа не запустится
int("abc")               # ValueError — можно перехватить

Как идёт поиск обработчика

ошибка в divide()
   └─ нет try → поднимается в main()
        └─ нет try → поднимается в модуль
             └─ нет обработчика → программа завершается
Если try/except найден на любом уровне — управление переходит в него.

Конструкция try … except

Базовая форма

Код в try выполняется; при ошибке указанного типа управление переходит в except.

try:
    n = int(input("Число: "))
    print(10 / n)
except ZeroDivisionError:
    print("Делить на ноль нельзя")
except ValueError:
    print("Нужно ввести число")
# ввод 0   → Делить на ноль нельзя
# ввод abc → Нужно ввести число

Получить объект ошибки: as

try:
    int("abc")
except ValueError as e:
    print(e)                  # invalid literal for int() with base 10: 'abc'
    print(type(e).__name__)   # ValueError
# после блока except имя e удаляется

Несколько исключений в одном except

Типы перечисляются в скобках (кортеж).

try:
    result = data["x"] / int(data["y"])
except (KeyError, ValueError, ZeroDivisionError) as e:
    print(f"Некорректные данные: {e!r}")

Порядок except важен

Проверяются сверху вниз, срабатывает первый подходящий. Частные исключения ставьте выше общих, иначе общий «перехватит» всё.

try:
    open("no_file.txt")
except FileNotFoundError:      # частный
    print("Файл не найден")
except OSError:                # более общий
    print("Ошибка ввода-вывода")
except Exception:              # самый общий — последним
    print("Что-то другое")

except Exception и «голый» except

try:
    run()
except Exception as e:         # ловит почти все ошибки программы
    print("Ошибка:", e)

try:
    run()
except:                        # ПЛОХО: ловит и Ctrl+C, и sys.exit()
    pass

«Голый» except: и except BaseException скрывают KeyboardInterrupt и SystemExit. Используйте конкретные типы или хотя бы Exception.

Вложенные try

try:
    f = open("data.txt")
    try:
        value = int(f.readline())
    except ValueError:
        value = 0                      # внутренняя ошибка обработана локально
    finally:
        f.close()
except FileNotFoundError:
    value = -1                         # внешняя — другая ошибка
print(value)

Обработка в вызывающем коде

Функция может не обрабатывать ошибку, а оставить решение вызывающему.

def read_age(text):
    return int(text)                   # ошибка поднимется выше

try:
    age = read_age("двадцать")
except ValueError:
    age = None
print(age)    # None

Не перехватывайте лишнее

Держите в try только строки, где ошибка ожидаема.

# плохо: любая ошибка внутри будет «обработана» как ValueError
try:
    n = int(text)
    result = complicated(n)
    save(result)
except ValueError: ...

# хорошо
try:
    n = int(text)
except ValueError:
    n = 0
result = complicated(n)

else и finally

else: если ошибки не было

Блок else выполняется, только когда в try исключений не произошло. Ошибки внутри else не перехватываются соседними except.

try:
    n = int(input("Число: "))
except ValueError:
    print("Не число")
else:
    print("Квадрат:", n * n)       # только если ввод корректен

finally: выполняется всегда

Код в finally срабатывает при любом исходе: успех, ошибка, return, break. Используется для освобождения ресурсов.

f = open("log.txt", "w")
try:
    f.write("запись\n")
    risky()
finally:
    f.close()                      # файл закроется в любом случае

Полная форма

try:
    value = int(text)
except ValueError:
    print("ошибка преобразования")
else:
    print("успех:", value)
finally:
    print("всегда выполняется")

Порядок выполнения

нет ошибки:           try → else → finally
ошибка перехвачена:   try (до ошибки) → except → finally
ошибка не перехвачена: try (до ошибки) → finally → ошибка идёт вверх

try … finally без except

Ошибка не подавляется, но очистка выполняется.

def work():
    try:
        return "результат"
    finally:
        print("очистка")
work()    # печатает «очистка», возвращает 'результат'

Ловушка: return в finally

return, break или continue внутри finally отменяют исключение: ошибка пропадает бесследно. Избегайте этого.

def bad():
    try:
        raise ValueError("потеряется")
    finally:
        return "ошибки как не бывало"
bad()    # 'ошибки как не бывало'

Встроенные исключения

Все исключения — классы, образующие иерархию. except ловит указанный класс и всех его потомков.

Иерархия (сокращённо)

BaseException
├── SystemExit               sys.exit()
├── KeyboardInterrupt        Ctrl+C
├── GeneratorExit
└── Exception                ← от него наследуются «обычные» ошибки
    ├── ArithmeticError → ZeroDivisionError, OverflowError
    ├── AssertionError
    ├── AttributeError
    ├── EOFError
    ├── ImportError → ModuleNotFoundError
    ├── LookupError → IndexError, KeyError
    ├── NameError → UnboundLocalError
    ├── OSError → FileNotFoundError, PermissionError,
    │            FileExistsError, TimeoutError, ConnectionError
    ├── RuntimeError → RecursionError, NotImplementedError
    ├── StopIteration
    ├── SyntaxError → IndentationError
    ├── TypeError
    └── ValueError → UnicodeError (UnicodeDecodeError)

Что это даёт

try:
    d = {"a": 1}

except LookupError:        # ловит и KeyError, и IndexError

Информация об исключении

Сообщение, тип, аргументы

try:
    1 / 0
except ZeroDivisionError as e:
    str(e)               # 'division by zero'
    repr(e)              # "ZeroDivisionError('division by zero')"
    e.args               # ('division by zero',)
    type(e).__name__     # 'ZeroDivisionError'

Атрибуты OSError

try:
    open("no.txt")
except FileNotFoundError as e:
    e.errno          # 2
    e.strerror       # 'No such file or directory'
    e.filename       # 'no.txt'

Трассировка в виде текста

import traceback
try:
    1 / 0
except ZeroDivisionError:
    traceback.print_exc()             # напечатать в stderr
    text = traceback.format_exc()     # получить как строку
    # e.__traceback__ — объект трассировки

Запись в журнал (logging)

logging.exception записывает сообщение уровня ERROR вместе с трассировкой. Вызывается внутри except.

import logging
logging.basicConfig(filename="app.log", level=logging.INFO,
                    format="%(asctime)s %(levelname)s %(message)s")
try:
    risky()
except Exception:
    logging.exception("Сбой при обработке заказа")

Заметки к ошибке (Python 3.11+)

try:
    int("abc")
except ValueError as e:
    e.add_note(f"Поле: возраст, строка 12")
    raise                             # заметка попадёт в traceback

Глобальный обработчик

Перехватывает необработанные исключения на верхнем уровне (например, для записи в журнал).

import sys
def handler(exc_type, exc, tb):
    if issubclass(exc_type, KeyboardInterrupt):
        sys.__excepthook__(exc_type, exc, tb)
        return
    print(f"Критическая ошибка: {exc}")
sys.excepthook = handler

Типовые шаблоны

Ввод до корректного значения

def read_int(prompt, lo=None, hi=None):
    while True:
        try:
            n = int(input(prompt))
        except ValueError:
            print("Введите целое число")
            continue
        if (lo is not None and n < lo) or (hi is not None and n > hi):
            print(f"Допустимо от {lo} до {hi}")
            continue
        return n

EAFP и LBYL

LBYL — «посмотри, прежде чем прыгнуть» (проверки заранее). EAFP — «проще попросить прощения»: выполнить и обработать ошибку. В Python принят EAFP.

# LBYL
if "key" in d:
    value = d["key"]
else:
    value = None
# EAFP
try:
    value = d["key"]
except KeyError:
    value = None
# а для словарей проще: d.get("key")

Значение по умолчанию

def to_int(text, default=0):
    try:
        return int(text)
    except (ValueError, TypeError):
        return default
to_int("42"), to_int("abc"), to_int(None)    # (42, 0, 0)

Повтор при неудаче

import time
for attempt in range(1, 4):
    try:
        data = fetch()
        break                                  # успех — выходим
    except ConnectionError as e:
        print(f"Попытка {attempt} не удалась: {e}")
        time.sleep(1)
else:
    raise RuntimeError("Сервер недоступен")   # все попытки исчерпаны

Пропустить плохие записи

rows = ["10", "x", "30", ""]
nums, bad = [], []
for r in rows:
    try:
        nums.append(int(r))

Конец ввода и выход из программы

    line = input()

raise: самостоятельно вызвать исключение

raise нужен, чтобы сообщить об ошибке самому: когда данные некорректны, нарушено условие или нужно пробросить ошибку дальше.

Формы raise

raise ValueError("сообщение")      # с текстом (чаще всего)
raise ValueError                   # класс без аргументов
raise ValueError("a", 42)          # несколько аргументов → e.args
err = KeyError("id")
raise err                          # готовый объект
raise                              # внутри except: повторить текущую ошибку

Проверка аргументов

Неверный тип — TypeError, неверное значение — ValueError.

def set_age(age):
    if not isinstance(age, int):
        raise TypeError(f"age должен быть int, получен {type(age).__name__}")
    if not 0 <= age <= 120:
        raise ValueError(f"age вне диапазона 0–120: {age}")
    return age

try:
    set_age(-5)
except ValueError as e:
    print(e)        # age вне диапазона 0–120: -5

Повторный raise (re-raise)

Обработать ошибку частично (записать в журнал, откатить изменения) и передать дальше. «Голый» raise сохраняет исходную трассировку.

try:
    save_to_db(order)
except DatabaseError as e:
    logging.error("Не удалось сохранить: %s", e)
    rollback()
    raise                     # вызывающий код тоже узнает об ошибке

raise … from: цепочка причин

Заменяет низкоуровневую ошибку понятной и сохраняет исходную как причину (__cause__). В traceback видны обе.

def load_port(text):
    try:
        return int(text)
    except ValueError as e:
        raise RuntimeError("Некорректный порт в настройках") from e

try:
    load_port("abc")
except RuntimeError as e:
    e.__cause__        # ValueError("invalid literal ...")

from None: скрыть причину

Если исходная ошибка — технические детали, которые пользователю не нужны.

try:
    value = config["timeout"]
except KeyError:
    raise ValueError("Не задан параметр timeout") from None

Автоматическая цепочка (__context__)

Если новая ошибка возникает внутри except без from, Python сам запоминает предыдущую в __context__.

ValueError: ...
During handling of the above exception, another exception occurred:
RuntimeError: ...      # (без from)

...was the direct cause of the following exception:
RuntimeError: ...      # (с from e)

Заготовки: NotImplementedError

class Shape:
    def area(self):
        raise NotImplementedError("Подкласс должен реализовать area()")

class Square(Shape):
    def __init__(self, a): self.a = a
    def area(self): return self.a ** 2

Square(3).area()    # 9
Shape().area()      # NotImplementedError

Выход из программы

import sys
sys.exit(0)                   # успех (SystemExit)
sys.exit(1)                   # ошибка, код возврата 1
sys.exit("Критическая ошибка")   # текст в stderr, код 1
raise SystemExit(2)           # то же самое

assert: проверка допущений

assert условие, "сообщение" вызывает AssertionError, если условие ложно. Это инструмент разработчика: проверка того, что в программе «не может быть» неверно.

Синтаксис

assert 2 + 2 == 4                      # всё хорошо, ничего не происходит
assert 2 + 2 == 5                      # AssertionError
assert 2 + 2 == 5, "арифметика сломалась"
# AssertionError: арифметика сломалась

# эквивалент:
if __debug__ and not условие:
    raise AssertionError(сообщение)

Типовое применение

def average(nums):
    assert len(nums) > 0, "список не должен быть пустым"   # предусловие
    result = sum(nums) / len(nums)
    assert min(nums) <= result <= max(nums)               # постусловие
    return result

class Account:
    def withdraw(self, amount):
        self.balance -= amount
        assert self.balance >= 0, "баланс не может быть отрицательным"   # инвариант

assert можно отключить

При запуске с ключом -O все assert пропускаются. Поэтому они не годятся для проверки входных данных и безопасности.

python app.py        # assert работают
python -O app.py     # assert отключены (__debug__ == False)
def delete_user(user):
    assert user.is_admin          # ПЛОХО: при -O проверка исчезнет
    ...
def delete_user(user):
    if not user.is_admin:         # ХОРОШО
        raise PermissionError("Нужны права администратора")

Ловушки assert

# 1. Скобки создают кортеж — он всегда «истинный»
assert (x > 0, "x должен быть положительным")   # проверка НЕ работает
assert x > 0, "x должен быть положительным"     # верно

# 2. Не помещайте в assert действия с побочным эффектом
assert queue.pop() is not None   # при -O pop() не вызовется!

assert в тестах

# pytest
import pytest
def test_divide():
    assert divide(6, 3) == 2
    with pytest.raises(ZeroDivisionError):
        divide(1, 0)

# unittest
import unittest
class T(unittest.TestCase):
    def test_div(self):
        self.assertEqual(divide(6, 3), 2)
        with self.assertRaises(ZeroDivisionError):
            divide(1, 0)

Собственные исключения

Свой класс ошибки делает код выразительнее: InsufficientFundsError понятнее, чем ValueError, и его можно ловить отдельно. Наследуйтесь от Exception (не от BaseException).

Самое простое

class EmptyBasketError(Exception):
    """Корзина пуста."""

def checkout(basket):
    if not basket:
        raise EmptyBasketError("Нельзя оформить пустую корзину")

try:
    checkout([])
except EmptyBasketError as e:
    print(e)        # Нельзя оформить пустую корзину

С данными и сообщением

Дополнительные поля помогают обработчику принять решение.

class InsufficientFundsError(Exception):
    def __init__(self, balance, amount):
        super().__init__(f"Недостаточно средств: баланс {balance}, нужно {amount}")
        self.balance = balance
        self.amount = amount

try:
    raise InsufficientFundsError(100, 250)
except InsufficientFundsError as e:
    print(e)                               # сообщение
    print("Не хватает:", e.amount - e.balance)   # 150

Иерархия ошибок приложения

Общий базовый класс позволяет перехватить все ошибки приложения одной строкой или обработать каждую отдельно.

class AppError(Exception):
    """Базовая ошибка приложения."""

class ValidationError(AppError): ...
class NotFoundError(AppError): ...
class AccessDeniedError(AppError): ...

try:
    handle_request()
except NotFoundError:
    print("404")
except AppError as e:         # любая другая ошибка приложения
    print("Ошибка:", e)

Свой __str__ и код ошибки

class ApiError(Exception):
    def __init__(self, status, message):
        super().__init__(status, message)
        self.status, self.message = status, message
    def __str__(self):
        return f"[{self.status}] {self.message}"

raise ApiError(404, "Страница не найдена")
# ApiError: [404] Страница не найдена

Наследование от встроенных

Если ошибка по смыслу — частный случай встроенной, наследуйтесь от неё: старый код с except ValueError продолжит работать.

class NegativeAgeError(ValueError):
    pass

try:
    raise NegativeAgeError("возраст < 0")
except ValueError as e:        # поймали как ValueError
    print(type(e).__name__)    # NegativeAgeError

Оборачивание чужих ошибок

Библиотечные ошибки превращают в ошибки вашего уровня, сохраняя причину.

class StorageError(AppError): ...

def read_note(path):
    try:
        with open(path, encoding="utf-8") as f:
            return f.read()
    except OSError as e:
        raise StorageError(f"Не удалось прочитать {path}") from e

  • Один модуль errors.py для всех исключений проекта.
  • Одна базовая ошибка приложения, от неё — конкретные.
  • Сообщение отвечает на вопрос «что пошло не так и с какими данными».
  • Не создавайте исключение на каждую мелочь: если обработчик у всех один — хватит одного класса.

Менеджеры контекста (with)

with гарантирует освобождение ресурса даже при ошибке. Это замена try … finally для файлов, соединений, блокировок.

with open

try:
    with open("data.txt", encoding="utf-8") as f:
        text = f.read()               # файл закроется сам
except FileNotFoundError:
    text = ""
# внутри with ошибка тоже закроет файл

Несколько ресурсов

with open("in.txt") as src, open("out.txt", "w") as dst:
    dst.write(src.read().upper())

Свой менеджер: класс

__exit__ вызывается всегда. Если он вернёт True, исключение подавляется.

import time
class Timer:
    def __enter__(self):
        self.t0 = time.perf_counter()
        return self
    def __exit__(self, exc_type, exc, tb):
        print(f"{time.perf_counter() - self.t0:.3f} с")
        return False              # ошибку не подавлять

with Timer():
    sum(range(10**6))

Свой менеджер: contextmanager

from contextlib import contextmanager

@contextmanager
def transaction(db):
    db.begin()
    try:
        yield db                  # тело with выполняется здесь
    except Exception:
        db.rollback()
        raise
    else:
        db.commit()

suppress: молча игнорировать

import os
from contextlib import suppress
with suppress(FileNotFoundError):
    os.remove("tmp.txt")          # нет файла — не страшно

Группы исключений (Python 3.11+)

ExceptionGroup и except*

Позволяют сообщить сразу о нескольких независимых ошибках (например, при проверке формы или при параллельных задачах). Блок except* обрабатывает подходящие ошибки из группы.

try:
    raise ExceptionGroup("Ошибки валидации", [
        ValueError("имя пустое"),
        TypeError("возраст должен быть числом"),
        ValueError("некорректный email"),
    ])
except* ValueError as eg:
    for e in eg.exceptions:
        print("ValueError:", e)         # имя пустое / некорректный email
except* TypeError as eg:
    print("TypeError:", eg.exceptions[0])

Хорошие практики

Делайте

  • Ловите конкретные исключения.
  • Держите try коротким.
  • Освобождайте ресурсы через with или finally.
  • Пишите понятные сообщения с данными.
  • Записывайте ошибки в журнал (logging.exception).
  • Пробрасывайте ошибку дальше, если не можете обработать (raise).
  • Используйте raise … from при замене исключения.
  • Создавайте свою иерархию исключений для проекта.

Не делайте

  • except: pass — ошибка исчезает бесследно.
  • except Exception: print("ошибка") без деталей.
  • Ловить BaseException, KeyboardInterrupt без причины.
  • return в finally.
  • assert для проверки ввода пользователя.
  • Продолжать работу с некорректным состоянием после ошибки.
  • Использовать исключения вместо обычных if там, где ошибка — норма и в «горячем» цикле.

Мини-проекты

Каждый проект — отдельный файл, запуск: python имя_файла.py. Вместе они используют все конструкции: try / except / else / finally, raise, raise from, assert, свои исключения, with и группы исключений. Проект 5 требует Python 3.11+.

Проект 1: безопасный калькулятор (try / except / else / finally)

Цикл ввода без падений: некорректные числа, неизвестные операции, деление на ноль, Ctrl+C.

import operator

OPS = {"+": operator.add, "-": operator.sub,
       "*": operator.mul, "/": operator.truediv}

def read_number(prompt):
    while True:
        try:
            return float(input(prompt).replace(",", "."))
        except ValueError:
            print("Это не число, попробуйте ещё раз")

def main():
    print("Калькулятор. Выход: пустая операция или Ctrl+C")
    try:
        while True:
            a = read_number("a = ")
            op = input("операция (+ - * /): ").strip()
            if not op:
                break
            b = read_number("b = ")
            try:
                result = OPS[op](a, b)
            except KeyError:
                print(f"Неизвестная операция: {op!r}")
            except ZeroDivisionError:
                print("Деление на ноль невозможно")
            else:
                print(f"= {result:g}")            # только при успехе
            finally:
                print("-" * 20)                   # после каждого вычисления
    except (KeyboardInterrupt, EOFError):
        print("\nДо свидания")

main()

Проект 2: загрузка конфигурации (несколько except, raise from, logging)

Читает config.json. Нет файла — берёт значения по умолчанию, битый файл — понятная ошибка с причиной, неверный порт — ValueError.

import json
import logging

logging.basicConfig(level=logging.INFO, format="%(levelname)s: %(message)s")

class ConfigError(Exception):
    """Ошибка загрузки конфигурации."""

DEFAULTS = {"host": "localhost", "port": 8080, "debug": False}

def validate(cfg):
    port = cfg["port"]
    if not isinstance(port, int) or not 1 <= port <= 65535:
        raise ValueError(f"port должен быть числом 1–65535, получено {port!r}")

def load_config(path):
    try:
        with open(path, encoding="utf-8") as f:
            data = json.load(f)
    except FileNotFoundError:
        logging.warning("Файл %s не найден, используются значения по умолчанию", path)
        return dict(DEFAULTS)
    except json.JSONDecodeError as e:
        raise ConfigError(f"Некорректный JSON в {path}: строка {e.lineno}") from e
    except PermissionError as e:
        raise ConfigError(f"Нет доступа к {path}") from e
    else:
        if not isinstance(data, dict):
            raise ConfigError("Корень файла должен быть JSON-объектом")
        config = {**DEFAULTS, **data}
        validate(config)
        return config

if __name__ == "__main__":
    try:
        cfg = load_config("config.json")
    except (ConfigError, ValueError) as e:
        logging.error("Запуск невозможен: %s", e)
        raise SystemExit(1)
    print("Конфигурация:", cfg)

# нет файла    → WARNING ... / Конфигурация: {'host': 'localhost', 'port': 8080, 'debug': False}
# {"port": "abc"} → ERROR: Запуск невозможен: port должен быть числом 1–65535, получено 'abc'
# {"port": 9000   (обрыв) → ERROR: Запуск невозможен: Некорректный JSON в config.json: строка 1

Проект 3: банковский счёт (свои исключения, raise, assert)

Иерархия ошибок предметной области, проверка входных данных через raise, внутренние инварианты через assert, откат перевода при ошибке.

class BankError(Exception):
    """Базовое исключение банка."""

class InvalidAmountError(BankError):
    def __init__(self, amount):
        super().__init__(f"Некорректная сумма: {amount!r}")
        self.amount = amount

class InsufficientFundsError(BankError):
    def __init__(self, balance, amount):
        super().__init__(f"Недостаточно средств: на счёте {balance}, нужно {amount}")
        self.balance, self.amount = balance, amount

class Account:
    def __init__(self, owner, balance=0):
        if balance < 0:
            raise ValueError("начальный баланс не может быть отрицательным")
        self.owner, self.balance = owner, balance

    @staticmethod
    def _check(amount):
        if not isinstance(amount, (int, float)) or amount <= 0:
            raise InvalidAmountError(amount)

    def deposit(self, amount):
        self._check(amount)
        self.balance += amount
        assert self.balance >= 0, "баланс стал отрицательным"   # инвариант

    def withdraw(self, amount):
        self._check(amount)
        if amount > self.balance:
            raise InsufficientFundsError(self.balance, amount)
        self.balance -= amount
        assert self.balance >= 0

def transfer(src, dst, amount):
    src.withdraw(amount)
    try:
        dst.deposit(amount)
    except BankError:
        src.deposit(amount)        # откат
        raise                      # и сообщаем об ошибке дальше

a, b = Account("Аня", 100), Account("Боря")
for amount in (30, -5, "10", 500):
    try:
        transfer(a, b, amount)
        print(f"Перевод {amount} выполнен: {a.balance} / {b.balance}")
    except InvalidAmountError as e:
        print("Ошибка суммы:", e)
    except InsufficientFundsError as e:
        print("Отказ:", e, f"(не хватает {e.amount - e.balance})")
    except BankError as e:
        print("Банковская ошибка:", e)
# Перевод 30 выполнен: 70 / 30
# Ошибка суммы: Некорректная сумма: -5
# Ошибка суммы: Некорректная сумма: '10'
# Отказ: Недостаточно средств: на счёте 70, нужно 500 (не хватает 430)

Проект 4: повтор операции и этапы (декоратор, with, finally, raise from)

Декоратор повторяет «капризную» функцию, при исчерпании попыток поднимает RetryError с причиной. Менеджер контекста stage сообщает об успехе или ошибке этапа.

import functools, random, time
from contextlib import contextmanager, suppress

class RetryError(Exception):
    """Все попытки исчерпаны."""

def retry(times=3, delay=0.2, exceptions=(ConnectionError, TimeoutError)):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            last = None
            for attempt in range(1, times + 1):
                try:
                    return func(*args, **kwargs)
                except exceptions as e:
                    last = e
                    print(f"  попытка {attempt}/{times} не удалась: {e}")
                    time.sleep(delay)
            raise RetryError(f"{func.__name__}: все {times} попыток неудачны") from last
        return wrapper
    return decorator

@retry(times=4)
def fetch():
    if random.random() < 0.7:
        raise ConnectionError("сервер не отвечает")
    return "данные получены"

@contextmanager
def stage(name):
    print(f"▶ {name}")
    try:
        yield
    except Exception as e:
        print(f"✖ {name}: {type(e).__name__}: {e}")
        raise
    else:
        print(f"✔ {name}")
    finally:
        print(f"  (этап «{name}» завершён)")

random.seed(1)                       # для воспроизводимого результата
with suppress(RetryError):           # исчерпание попыток не роняет программу
    with stage("загрузка"):
        print(fetch())
# при seed(1): одна неудачная попытка, затем успех:
# ▶ загрузка / попытка 1/4 не удалась: сервер не отвечает / данные получены / ✔ загрузка

Проект 5: валидатор данных (ExceptionGroup, except*, assert)

Проверяет форму целиком и сообщает обо всех ошибках сразу. В конце — самопроверка через assert. Python 3.11+.

def validate_user(data):
    errors = []
    if not str(data.get("name", "")).strip():
        errors.append(ValueError("имя обязательно"))
    age = data.get("age")
    if not isinstance(age, int):
        errors.append(TypeError("возраст должен быть целым числом"))
    elif not 0 <= age <= 120:
        errors.append(ValueError(f"возраст вне диапазона: {age}"))
    if "@" not in str(data.get("email", "")):
        errors.append(ValueError("некорректный email"))
    if errors:
        raise ExceptionGroup("Ошибки валидации", errors)

# --- самопроверка (assert) ---
assert validate_user({"name": "Аня", "age": 20, "email": "a@b.c"}) is None
try:
    validate_user({})
    raise AssertionError("ожидалось исключение")
except ExceptionGroup as eg:
    assert len(eg.exceptions) == 3, "должно быть 3 ошибки"

# --- использование ---
try:
    validate_user({"name": "", "age": "20", "email": "abc"})
except* ValueError as eg:
    for e in eg.exceptions:
        print("ValueError:", e)
except* TypeError as eg:
    for e in eg.exceptions:
        print("TypeError:", e)
# ValueError: имя обязательно
# ValueError: некорректный email
# TypeError: возраст должен быть целым числом

Идеи для развития: объединить проекты в одно приложение с общим модулем errors.py, добавить запись всех ошибок в журнал через logging.exception, покрыть тестами на pytest с pytest.raises.

Совет: ловите только то, что умеете обработать, а остальное пусть поднимается выше. Ошибка с понятным сообщением и сохранённой причиной экономит часы отладки.
